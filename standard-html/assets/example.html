Standard HTML: house style

2026-07-12~/.claude/skillsDesign brief

This document is the reference implementation of the house style. It exists to be argued with: every component the stylesheet ships is used at least once below, so anything you dislike here is something you can strike from assets/style.css and never see again. The style takes its cues from Andrew Kelley's blog — a plain document on a plain background, system font, no ornament — extended only where plans and audits genuinely need structure that prose cannot carry.

The one rule

These documents never adopt the theme of the project they live in. Not its fonts, not its brand colors, not its design tokens. A plan for a game and a plan for a payments backend look identical, because the document is a note about the work rather than a piece of it, and because your eye should never have to re-learn the layout when you switch repos.

Note The stylesheet is pasted into every document rather than linked. A doc that loses its formatting when you move it, email it, or open it from disk is not a document, it is a build artifact.

Typography and prose

Body text is system-ui at 17px on a 72em measure, left-justified against the gutter rather than centered in the window. Links are blue and underlined because that is what a link looks like. Code is ui-monospace, boxed inline and tinted in blocks. Paths get the mono face without the box, so a line like src/api/handlers.rs:214 reads as a location rather than a snippet.

Quotes are set off with a rule and muted, for when you are citing a spec, an error message, or something the user said three turns ago.

Headings go three deep

An h1 for the title with a rule under it, h2 for sections, h3 for the rare subsection. If you find yourself wanting an h4, the document probably wants splitting instead.

Decisions

A definition list is the honest shape for a decision record: the choice on the left, the reason on the right, nothing else competing for attention.

Font
System UI stack. No web fonts — they add a network dependency and a flash of unstyled text to a document whose entire job is to be readable offline.
Dark mode
Follows prefers-color-scheme. No toggle: the OS already knows the answer and a toggle is a widget to maintain.
Measure
72em, same as Kelley. Generous for prose, but it means a findings table never has to scroll, and long code lines stay on one line.
Alignment
Left, not centered. The document starts at the same x-position no matter how wide the window is, so nothing reflows sideways when you resize.
Color
Four semantic colors and three greys. Severity needs to be legible at a glance; nothing else in the document needs to be colored at all.

Plans

Phased work uses a task list with an explicit state per item, so a plan and a progress report are the same document at two points in time.

  • Write the audit skill and the standard-html skill.
  • Lift a house style from the Kelley stylesheet and extend it for tables, callouts, and status.
  • Get this document in front of you and cut what you do not like.
  • Run a real audit on a real repo and see whether the report format survives contact.

Findings tables

The reason HTML exists in this workflow. The same content in Markdown is a thicket of pipes that neither of us can read, and the status column is the first thing to break. Reasoning lives in the prose around the table; the cells hold short enumerable facts.

AreaSeverityFinding
assets/style.css solid Renders correctly in light and dark, degrades sanely when printed.
SKILL.md unproven The trigger description has not yet been tested against a real "make me a plan" request.
audit/SKILL.md untested The verification step is the load-bearing one and has never run against a live codebase.

Warning Callouts come in three flavors and should stay rare. A document where everything is boxed is a document where nothing is emphasized.
Resolved The third flavor, for a risk that has been checked and cleared.

Code

Blocks are bordered and tinted — the one Kelley signature worth keeping verbatim — and scroll inside their own box rather than pushing the page sideways.

/* The whole of Kelley's stylesheet, essentially: */
body {
  font-family: system-ui, -apple-system, Roboto, "Segoe UI", sans-serif;
}
pre {
  background-color: #eee;
  border: 1px solid #3a3a3a;
  padding: 0.5em;
}
@media (prefers-color-scheme: dark) {
  body { background-color: black; color: white; }
  a    { color: #89a6ff; }
}

What to tell me

Things worth having an opinion about: the 17px body size, whether the tinted <pre> border is too heavy, whether tags should be colored text or filled pills, and whether the task-list [x] markers are charming or twee. Anything you cut, I will cut from the stylesheet so it never comes back.
